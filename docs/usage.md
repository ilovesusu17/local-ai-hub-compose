# New-API 渠道接入与配置实战指南 (Usage Guide)

本文档介绍如何在 **New-API** 控制台中正确挂载各类本地反代服务（如 WorkBuddy、Trae、Qoder、CLIProxy 等），避免常见的配置陷阱。

---

## 1. 核心接入原则

1. **统一使用容器名作为 API 地址**：
   - 处于同一 `ai-hub-net` 自定义桥接网络下的容器，互访**必须使用容器名**加容器内部端口。
   - **严禁使用 `http://host.docker.internal:...`**（自定义网络内部无法解析此域名，会导致 `no such host` 错误）。
2. **一个模型名只挂一条渠道**：
   - 避免在不同渠道中配置完全相同的模型名，否则易导致轮询混乱或特定号池无法命中；
   - 建议通过 New-API 的「模型重定向」功能将客户端常用模型名称映射到具体后端的实际模型 ID。
3. **保持用户账户总额度充裕**：
   - 客户端分发的普通令牌（Token）即便利选了「无限制」，底层的扣费逻辑依然扣减其所属**用户账号自身的总余额**；
   - 务必在「管理后台 -> 用户管理」中将管理员或实际用户的额度设为一个极大的安全值（例如 100000000000），防止并发大上下文请求扣穿导致全链路 403。

| 渠道服务 | 类型 | 代理/Base URL | 密钥 (Key) | 模型列表 (示例) | 注意事项 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **WorkBuddy (国际)** | OpenAI / 自定义 | `http://workbuddy:8788` | 填入 WorkBuddy 国际 Key | `claude-3-5-sonnet`, `gpt-4o` | 对应国际账号池，出口走海外 |
| **WorkBuddy (国内)** | OpenAI / 自定义 | `http://workbuddy:8788` | 填入 WorkBuddy 国内 Key | `deepseek-chat`, `qwen-plus` | 对应国内账号池，两池相互隔离 |

## 3. 双区账号池与权重调优建议

- **双 Key 隔离**：如果同一个反代服务区分了国内版与国际版账号池，在 New-API 中应当分别创建两条渠道（例如命名为 `WorkBuddy-Intl` 和 `WorkBuddy-CN`），分别填入两套 Key。
- **权重与号池切换**：若在反代服务内部调整了各账号的轮询权重，由于底层对活跃连接具有 **KV 缓存会话粘性**，正在进行中的对话通常仍会走初次命中的账号。若需立即换号，可在反代后台临时禁用旧号或在客户端重置新对话。
